# 报告输出模板 — company-due-diligence

> 大模型拿到 `data_fetcher.py all` 的 JSON 后，按本模板产出最终报告。
> 交付两份：Markdown（正文）+ 交互式 HTML（assets/report-template.html 红绿灯仪表盘）。
> 脚本已自动生成报告**骨架**（output/<公司名>/<公司名>.md），大模型负责：
> 核实证据、补充人工渠道信息、提炼坑点与提问清单、下结论。

## 报告结构（九段）

1. **结论速览**：评分 /100、🟢🟡🔴 信号灯、一句话结论（值不值得投递）
2. **主体识别**：消歧结果（推荐工商主体 + 同名候选），强调"平台名≠工商全称"
3. **基础工商信息**：法定代表人 / 注册资本 / 成立时间 / 状态标签（爱企查面板）
4. **红线核验表**：7 条红线 × {🚨命中 | ❓未验证 | ✅未见信号}，每条带证据链接
5. **风险信号扫描**：每个关键词的命中数 + 强信号，附证据链接
6. **员工评价入口**：平台 + 链接列表（原文由用户自行打开）
7. **坑点清单**：3–5 个具体坑点，每条附风险描述 + 证据
8. **面试重点提问清单**：可勾选的提问列表（进 HTML）
9. **manual_required**：所有需要人工核验的事项（官方渠道 + 验证码站点 + 疑似同名）

## 结论判定规则

| 状态 | 条件 | 结论模板 |
|---|---|---|
| 🔴 红灯 | 任一红线命中，或评分 <40 | 不建议投递。命中红线 X：…… |
| 🟡 黄灯 | 评分 40–69，或存在未验证红线 | 谨慎投递。必须核实：…… |
| 🟢 绿灯 | 评分 ≥70 且无命中红线 | 可正常评估。注意：…… |

## 坑点清单写作要求（用户核心诉求）

- **3–5 个具体坑点**，每个 = 风险描述 + 证据链接 + "面试时如何问"；
- 优先写"和钱/合同/稳定性直接相关"的坑：合同主体、社保主体、发薪准时性、
  试用期风险、外包/派遣、加班文化、裁员传闻；
- 坑点必须来自信号证据，不许编造；证据弱就写"需核实"。

## 面试提问清单（内置默认 8 问，可增删）

1. 合同与哪家公司主体签署？社保公积金缴纳主体与比例？
2. 试用期多长、薪资结构？绩效是否有书面考核标准？
3. 近一年是否有裁员/降薪/欠薪？离职率如何？
4. 发薪日与延迟记录？
5. 正编/外包/项目制？合同期限与续签条件？
6. 加班频率与加班费/调休政策？
7. 公司近一年诉讼/仲裁情况？经营现金流？
8. 直属上级与团队规模、汇报关系？

## HTML 仪表盘（assets/report-template.html）

- 自包含单文件（内联 CSS/JS），无网络依赖；
- 数据注入方式：`<script id="report-data" type="application/json">__REPORT_JSON__</script>`，
  `data_fetcher.py all` 已自动完成注入并输出 `<公司名>.html`；
- 交互：红线核验表、坑点卡片、评分环、可勾选提问清单；
- 微调建议：改模板配色/文案直接编辑 HTML；字段名与 JSON 保持一致。

## 示例（某公司 Case 复盘结论）

> 黄灯 → 疑似红线。同名主体多（多个地区注册主体），
> 命中"某公司劳动争议二审判决书""多家企业欠薪黑名单"
> 等线索，但无法确认是否招聘信息对应的主体本身 → 红线全部标未验证，
> 报告结论为：**需先确认招聘主体，再人工核验执行/仲裁记录**。
